# سیستم سیگنال‌دهی دستی معاملات آپشن بورس تهران

ربات بازار آپشن بورس تهران را رصد می‌کند و وقتی شرایط یک استراتژی برقرار شد،
یک **سیگنال معاملاتی** (نه سفارش خودکار) تولید و از طریق تلگرام / لاگ / کنسول نمایش می‌دهد.
کاربر خودش سیگنال را دستی در سامانه معاملاتی‌اش اجرا می‌کند.

> ⚠️ **هیچ اتصالی به API خرید/فروش کارگزاری در این پروژه وجود ندارد.**
> فقط یک اینترفیس انتزاعی خالی (`execution/order_executor_interface.py`) برای آینده گذاشته شده
> که پیاده‌سازی واقعی‌اش را بعداً خود کاربر می‌دهد.

**وضعیت فعلی:** مایل‌استون ۱ کامل + **داده واقعی بازار وصل شد** (TSETMC، بدون لاگین).
**۴۲۲ تست پاس** (تأییدشده، همه روی داده‌ی واقعی). برای اجرا اول بخش «آماده‌سازی محیط» را ببینید.

## داشبورد وب

راه راحت‌تر برای دیدن سیگنال‌ها و تغییر تنظیمات، بدون دست‌زدن به yaml.
دابل‌کلیک روی `8-dashboard.bat`، یا:

```powershell
.\.venv\Scripts\python.exe -m web
```

مرورگر خودکار روی `http://127.0.0.1:8787` باز می‌شود.

| تب | چه کاری می‌کنید |
|---|---|
| **سیگنال‌ها** | سیگنال‌های ثبت‌شده با فیلتر استراتژی و نماد؛ دکمه‌ی اجرای پاس رصد بازار |
| **استراتژی‌ها** | خاموش/روشن کردن هر استراتژی و تغییر پارامترهایش (پیش‌فرض هر پارامتر زیرش نوشته شده) |
| **نمادها** | انتخاب نمادهای پایه از لیست زنده‌ی بازار — فقط نمادهایی که واقعاً آپشن دارند |
| **ریسک** | دارایی حساب، درصد ریسک، سقف قرارداد، حد ضرر و سود |
| **ساختارها** | اسکن استردل/کالر/آیرون کاندور روی زنجیره واقعی + نقشه سفارش |
| **گزارش** | عملکرد سیگنال‌ها با قیمت واقعی، به تفکیک استراتژی و نماد + خروجی CSV |
| **حساب** | پوزیشن‌های واقعی کارگزاری (فقط خواندن) + تنظیم توکن از خود پنل |

تغییرات در `config/settings.yaml` ذخیره می‌شود و **از پاس بعدی** اعمال می‌گردد.

### ساختارهای چندپایه

| ساختار | پایه‌ها | سود | زیان |
|---|---|---|---|
| **لانگ استردل** | خرید کال + خرید پوت (هم‌استرایک) | نامحدود | محدود به پرمیوم |
| **کالر** | سهم + خرید پوت + فروش کال | سقف‌دار | کف‌دار |
| **آیرون کاندور** | خرید/فروش پوت + فروش/خرید کال | اعتبار خالص | عرض اسپرد − اعتبار |

از تب «ساختارها» روی زنجیره‌ی واقعی اسکن می‌شوند، با مرتب‌سازی بر اساس
ROI، ریسک/ریوارد، نقدشوندگی و ۷ معیار دیگر.

⚠️ **دو نکته که در محاسبات جدی گرفته شده‌اند:**

**۱. سود نامحدود `None` است، نه صفر.** لانگ استردل سود نامحدود دارد؛ اگر
صفر گزارش شود، در مرتب‌سازی ته لیست می‌افتد — برعکس واقعیت.

**۲. اجرای پایه‌ها اتمیک نیست.** در کشف API ایزی‌تریدر هیچ endpoint
سفارش چندپایه پیدا نشد، پس پایه‌ها **جدا** ثبت می‌شوند و بین آن‌ها
قیمت می‌تواند حرکت کند. هر ساختار چندپایه با برچسب «ریسک اجرای ناقص»
نشان داده می‌شود.

در تولید سیگنال هم پایه‌ها **اتمی** پردازش می‌شوند: اگر یک پایه از
فیلتر ریسک رد نشود، کل ساختار صرف‌نظر می‌شود — چون نصف استردل، استردل
نیست.

**واحدها:** `bid/ask` در این پروژه **هر واحد** است و ضرب در
`contract_size` فقط یک بار در `strategies/payoff.py` انجام می‌شود.
کمیسیون پیش‌فرض **صفر** است چون نرخ واقعی در پروژه نیست — حدس نمی‌زنیم.

### انتخاب منبع داده

از تب «نمادها» قابل تنظیم است. چرا ایزی‌تریدر گزینه‌ی زنجیره نیست:

| داده | TSETMC | ایزی‌تریدر |
|---|---|---|
| زنجیره کامل (strike، سررسید، اندازه) | ✅ **یک** درخواست | ❌ هر ISIN یک درخواست |
| مظنه و موقعیت باز | ✅ | ✅ |
| وجه تضمین اولیه/لازم | ❌ | ✅ |
| **دامنه مجاز نوسان** | ❌ | ✅ |
| نیاز به لاگین | ❌ | ✅ |

ایزی‌تریدر مشخصات قرارداد را فقط از `/option/api/Contracts/{isin}/symbol`
می‌دهد — برای ۱۳۸۶ قرارداد بازار یعنی **حدود ۷ دقیقه در هر پاس**.

پس به‌جای «یا این یا آن»، ترکیب می‌شوند: زنجیره از TSETMC، و با
`enrich_with_broker` فقط چند قرارداد نزدیک به قیمت پایه از کارگزاری
غنی می‌شوند (وجه تضمین و اندازه‌ی دقیق قرارداد).

اگر کارگزاری در دسترس نباشد، زنجیره بدون غنی‌سازی برمی‌گردد و برچسب
منبع هم **ادعای دروغ نمی‌کند** (`tsetmc` می‌ماند، نه `tsetmc+emofid`).

### گزارش عملکرد

دکمه‌ی «ارزیابی سیگنال‌های در انتظار» قیمت فعلی هر سیگنال را از TSETMC
می‌خواند و نتیجه را در جدول `signal_outcomes` ثبت می‌کند.

طبقه‌بندی نتیجه عمداً محافظه‌کار است:

| وضعیت | یعنی |
|---|---|
| **برد** | حد سود خورده، یا سررسید گذشته و سود مثبت |
| **باخت** | حد ضرر خورده، یا سررسید گذشته و سود منفی |
| **در انتظار** | نه حد سود نه حد ضرر — معامله هنوز **باز** است |

سیگنالی که ۰.۲٪ پایین است شکست نخورده؛ شمردنش به‌عنوان باخت نرخ برد را
بی‌معنا می‌کند. به همین دلیل هم وقتی هیچ سیگنالی نتیجه نگرفته، نرخ برد
**«نامعلوم»** است نه صفر.

خروجی CSV با `utf-8-sig` نوشته می‌شود تا اکسل فارسی را درست باز کند.

هر سیگنال برچسب **منبع داده** دارد: `tsetmc+tsetmc` یعنی داده واقعی،
نوار بالای صفحه هم همین را نشان می‌دهد. این پروژه داده‌ی ساختگی ندارد،
پس منبع همیشه واقعی است.

⚠️ **داشبورد هیچ سفارشی ثبت نمی‌کند** و راهی به لایه‌ی `execution` ندارد؛ یک تست
گارد AST که کل مخزن را می‌پاید این را تضمین می‌کند.

🔒 فقط روی `127.0.0.1` گوش می‌دهد، یعنی از کامپیوترهای دیگر در دسترس نیست.
داشبورد **احراز هویت ندارد** و تنظیمات را می‌نویسد، پس روی شبکه بازش نکنید.
(`--host` وجود دارد ولی هشدار می‌دهد.)

### شرط مالکیت برای Covered Call

Covered Call یعنی فروش کال روی سهمی که **داری**. بدون سهم، همان معامله یک
**کالِ لخت** است:

| | سود | زیان |
|---|---|---|
| Covered Call (با سهم) | محدود، سقف‌دار | افت سهم منهای پرمیوم |
| کالِ لخت (بدون سهم) | محدود به پرمیوم | **نامحدود** |

این دو یک استراتژی با پارامتر مختلف نیستند. قبلاً فقط یک جمله‌ی هشدار در
متن سیگنال بود؛ حالا اگر بدانیم سهم نداری، سیگنال **صادر نمی‌شود**.

**سه حالت، و تفاوت‌شان تصمیم‌ساز است:**

| `underlying_holding` | یعنی | رفتار |
|---|---|---|
| `None` | نامعلوم (کارگزاری خاموش) | سیگنال با هشدار — مثل قبل |
| کمتر از یک قرارداد | می‌دانیم کافی نیست | **رد** |
| کافی | می‌دانیم چقدر داری | سیگنال + تعداد قرارداد قابل پوشش |

تفکیک «نامعلوم» از «ندارد» عمدی و مهم است: اگر یک تایم‌اوت گذرا به «سهم
نداری» ترجمه می‌شد، همه‌ی سیگنال‌های Covered Call بی‌صدا حذف می‌شدند و
کاربر هیچ‌وقت نمی‌فهمید چرا. پس شکستِ خواندن هرگز صفر نمی‌شود.

```yaml
strategies:
  neutral_iv_spread:
    params:
      require_underlying_holding: true            # مالکیتِ ناکافی ⇒ رد
      skip_covered_call_if_holding_unknown: false # نامعلوم هم رد شود؟
```

**مرزِ معماری:** استراتژی یک **عدد** می‌گیرد
(`StrategyContext.underlying_holding`)، نه کلاینت کارگزاری. استراتژی حق
دسترسی به شبکه و حساب را ندارد و گاردِ AST همین را تست می‌کند — پس لایه‌ی
wiring دارایی را می‌خواند و به‌صورت داده پاس می‌دهد.

اندازه‌ی قرارداد از خودِ زنجیره می‌آید، نه از عددِ ثابت ۱۰۰۰: نمادی با
اندازه‌ی متفاوت وگرنه بی‌صدا غلط حساب می‌شد.

دارایی یک بار در هر پاس خوانده می‌شود (یک پاسخ همه‌ی نمادها را دارد) و
بین پاس‌ها کش نمی‌ماند — کاربر ممکن است وسط دو پاس سهم بخرد.

⚠️ مثل بقیه‌ی مسیرهای کارگزاری، روی حساب زنده تست نشده.

### دارایی حساب از کارگزاری

`account_equity` در yaml یک عدد دستی بود، و عدد دستی سریع کهنه می‌شود:
ریسک روی دارایی‌ای اندازه‌گیری می‌شد که دیگر وجود نداشت.

با روشن‌کردن `risk.use_broker_equity`، موجودی از
`GET /easy/api/money` خوانده می‌شود. بورس تهران تسویه‌ی T+۰/T+۱/T+۲ دارد،
پس «موجودی» یک عدد نیست:

| مقدار | معنی |
|---|---|
| `buy_power_t2` | قدرت خرید با احتساب پول تسویه‌نشده |
| `cash_t0` … `cash_t2` | نقد در هر مرحله‌ی تسویه |
| `margin_blocked` | وجه تضمین موقعیت‌های باز آپشن |

`equity` عمداً روی **قدرت خرید T+۲** بسته می‌شود: محافظه‌کارانه‌ترین
تعریفی که وجه بلوکه‌شده را کنار می‌گذارد. اگر کارگزاری آن را نفرستد،
به نقدِ T+۲ برمی‌گردد.

سه قید عمدی:

| حالت | رفتار |
|---|---|
| پیش‌فرض | **خاموش** — رفتار فعلی کسی بی‌خبر عوض نمی‌شود |
| خطای شبکه / توکن منقضی | بازگشت به عدد yaml + لاگ هشدار |
| موجودی صفر یا منفی | عدد yaml نگه داشته می‌شود |

قید سوم مهم است: حساب صفر یعنی هر سیگنال صفر قرارداد می‌گیرد، که فرقی با
نبودِ سیگنال ندارد ولی شبیه یک اشکال نرم‌افزاری به نظر می‌آید.

در تب **حساب** موجودی دیده می‌شود و در تب **ریسک** سوئیچش هست.

⚠️ **این مسیر روی حساب زنده تست نشده.** پیاده‌سازی روی شکل پاسخِ
ضبط‌شده‌ی سشن واقعی است (`docs/broker-emofid.md`)، و تست‌ها همان شکل را
می‌پوشانند — ولی خودِ درخواست هنوز به حساب واقعی نرفته است.

### تعدیل رویداد شرکتی

وقتی نماد پایه افزایش سرمایه می‌دهد، قیمت سهم به تناسب کاهش می‌یابد ولی
ارزش کل موقعیت نباید تغییر کند. بورس تهران همان روز استرایک و اندازه‌ی
قرارداد را تعدیل می‌کند. اگر ما تعدیل نکنیم:

* قیمت پایه یک‌شبه مثلاً یک‌هشتم می‌شود،
* استرایکِ **قدیم** با قیمتِ **جدید** مقایسه می‌شود،
* هر کالِ در-سود ناگهان عمیقاً بی‌ارزش به نظر می‌آید.

یک موج سیگنالِ کاملاً غلط، دقیقاً در پرنوسان‌ترین روز. این خطا بی‌صداست:
هیچ‌چیز نمی‌شکند، فقط اعداد غلط می‌شوند.

**فرمول** — نسبت = سهام قدیم ÷ سهام جدید

| مقدار | تعدیل |
|---|---|
| استرایک | × نسبت |
| اندازه قرارداد | ÷ نسبت |

یعنی `استرایک × اندازه` ثابت می‌ماند — همان قیدی که کل تعدیل بر پایه‌ی آن
تعریف شده، و صریح تست می‌شود. برای **سود نقدی** فرمول فرق دارد: استرایک
به اندازه‌ی مبلغ سود کم می‌شود و اندازه‌ی قرارداد دست‌نخورده می‌ماند.

**مرز مهم:** تعدیل فقط برای قراردادهایی معنا دارد که **قبل از** رویداد
نوشته شده‌اند. قراردادی که بعد از افزایش سرمایه منتشر شده، استرایکش از
اول تعدیل‌شده است؛ تعدیل دوباره خرابش می‌کند. پس `adjust` تاریخ انتشار
می‌گیرد و فقط رویدادهای بعد از آن را اعمال می‌کند.

**اثر روی بک‌تست** — اینجا خطا واقعاً گران بود. تاریخچه‌ی خام خودرو:

| تاریخچه | بزرگ‌ترین افت روزانه |
|---|---|
| خام | **−۸۳٫۸٪** در ۲۰۲۵-۰۴-۲۲ (ریزش ساختگی) |
| تعدیل‌شده | −۲۶٫۲٪ (یک حرکت واقعی) |

آن ریزش ۸۴٪ هرگز رخ نداده؛ فقط روزِ افزایش سرمایه است. هر استراتژی
تکنیکالی آن را سیگنال نزولیِ قوی می‌فهمد و کل نتیجه‌ی بک‌تست بی‌معنا
می‌شود. بک‌تست حالا تاریخچه را پیش از اجرا تعدیل می‌کند
(`backtest.adjust_corporate_actions`، پیش‌فرض روشن).

**منبع:** endpoint عمومی `GetInstrumentShareChange` با `numberOfShareOld`
و `numberOfShareNew`. برای سود نقدی، TSETMC منبع عمومیِ قابل‌اتکایی
نمی‌دهد، پس این نوع رویداد فقط دستی ثبت می‌شود — حدس نمی‌زنیم.

⚠️ یک تله‌ی واقعی: TSETMC گاهی یک رویداد را **دو روز پشت‌سرهم** گزارش
می‌کند (روی وبملت دیده شد). یکتاسازی روی خودِ گذارِ سهام انجام می‌شود نه
تاریخ، وگرنه نسبت دوبار اعمال می‌شد و استرایک نصفِ نصف می‌شد.

### عمق مظنه

تا اینجا فقط **بهترین** مظنه‌ی خرید/فروش را داشتیم. با یک سطح، این سؤال
بی‌جواب می‌ماند:

> اگر ۱۰ قرارداد بخرم، واقعاً به چه قیمتی پر می‌شود؟

در بازار آپشن تهران این سؤال حیاتی است. نمونه‌ی واقعی از همین بازار:

| سطح | بهترین فروش | حجم |
|---|---|---|
| ۱ | ۳۳٬۸۰۰ | **۱ قرارداد** |
| ۲ | ۳۴٬۰۰۰ | ۱۰۱ |
| ۳ | ۳۴٬۹۵۰ | ۵ |

نماد «۳۳٬۸۰۰» را نشان می‌دهد، ولی فقط برای یک قرارداد. سفارش ۱۰ تایی با
میانگین ۳۳٬۹۸۰ پر می‌شود و سفارش ۱۰٬۰۰۰ تایی **اصلاً پر نمی‌شود** —
کل عمق ۱۱۱ قرارداد است. سیگنالی که با مظنه‌ی سطح‌اول اندازه‌گیری شده،
روی کاغذ سودده است و در عمل با لغزش اجرا می‌شود.

`data/order_book.py` از endpoint عمومی `BestLimits` پنج سطح را می‌گیرد و
می‌گوید:

| پرسش | متد |
|---|---|
| با این حجم چه قیمتی پر می‌شود؟ | `fill_price(side, qty)` |
| چقدر بدتر از سطح اول؟ | `slippage(side, qty)` |
| اصلاً پر می‌شود؟ | `can_fill(side, qty)` |
| کل عمق یک سمت | `depth(side)` |

خریدِ ما روی **فروش**های دفتر پر می‌شود و برعکس؛ این وارونگی در یک جا
متمرکز شده و صریح تست می‌شود.

اگر سفارش پر نشود، `slippage` عمداً `None` برمی‌گرداند نه یک عدد
خوش‌بینانه — بهتر است بدانیم پر نمی‌شود تا اینکه فکر کنیم ارزان پر شده.

در تب **ساختارها**، تیکِ «عمق مظنه» را بزنید تا ستون عمق به نقشه‌ی سفارش
اضافه شود. پیش‌فرض خاموش است چون هر پایه یک درخواست جدا به TSETMC می‌خورد.

### تقویم معاملاتی

قبلاً «بازار باز است؟» فقط پنجشنبه و جمعه را تعطیل می‌دانست. یعنی در
نوروز و عاشورا هم ربات پاس رصد می‌زد و روی مظنه‌ی **دیروز** سیگنال
می‌ساخت — سیگنالی با قیمت بیات، که از سیگنال نداشتن بدتر است.

حالا `market/trading_calendar.py` تعطیلات را **از خودِ بازار** یاد
می‌گیرد: هر روزِ کاریِ غیرآخرهفته که در تاریخچه‌ی واقعی TSETMC کندلی
ندارد، تعطیل بوده.

چرا این‌طور و نه با یک جدول دستی؟ تعطیلات ایران دو دسته‌اند:

| دسته | مثال | مشکلش |
|---|---|---|
| شمسی-ثابت | ۱۳ فروردین، ۲۲ بهمن | هر سال سر جای خودش — قابل جدول‌کردن |
| قمری-متحرک | تاسوعا، عاشورا، اربعین | هر سال ~۱۱ روز جلو می‌آید — جدول دستی هر سال کهنه می‌شود |

پس دسته‌ی دوم را فقط بازار می‌داند. جدول شمسی-ثابت صرفاً برای روزهای
**آینده** به کار می‌رود که هنوز تاریخچه‌ای ندارند.

ترتیب تصمیم:

1. پنجشنبه/جمعه → تعطیل (قطعی، بدون نیاز به داده)
2. تعطیلیِ یادگرفته‌شده از تاریخچه‌ی واقعی → معتبرترین منبع
3. جدول شمسی-ثابت → فقط بیرون بازه‌ی تاریخچه

نتیجه روی داده‌ی زنده: **۳۶ روز تعطیل** در یک سال گذشته، شامل نوروز
۱۴۰۵ و تعطیلات قمری‌ای که هیچ جدول ثابتی نمی‌توانست بداند.

```yaml
trading_calendar:
  learn_from_market: true      # یادگیری از تاریخچه واقعی
  reference_symbol: خودرو      # نماد مرجع؛ باید پرمعامله باشد
  learn_days: 365
  cache_path: var/trading_calendar.json
  extra_holidays: []           # تعطیلی اضطراری که هنوز در تاریخچه نیامده
```

نماد مرجع باید پرمعامله باشد، وگرنه «نبودِ کندل» یعنی توقف نماد، نه
تعطیلی بازار. شکست یادگیری (قطعی شبکه) خطا نمی‌دهد و به رفتار قبلی
(فقط آخرهفته) برمی‌گردد — نداشتن تقویم دقیق نباید کل پاس رصد را بخواباند.

تبدیل تاریخ شمسی هم داخل همین ماژول است (بدون وابستگی خارجی) و رفت‌وبرگشتش
روی ۳۰ سال تست شده.

## اجرای سریع با batch file (ساده‌ترین راه)

روی هر فایل **دابل‌کلیک** کنید — نیازی به ترمینال، `cd`، یا به‌خاطر سپردن دستور نیست.
اگر venv نباشد، اولین اجرا خودش می‌سازدش.

| فایل | کار | لاگین لازم؟ |
|---|---|---|
| `1-signal-test.bat` | یک پاس با داده واقعی، بدون ذخیره و تلگرام | ❌ |
| `2-signal-live.bat` | سیگنال روی داده واقعی TSETMC | ❌ |
| `3-discover-api.bat` | **کشف API ایزی‌تریدر** — Chrome باز می‌کند | ✅ خودتان |
| `4-har-to-api.bat` | تبدیل فایل HAR به فهرست API | ✅ خودتان |
| `5-signal-live-force.bat` | داده واقعی، بدون بررسی ساعت بازار | ❌ |
| `6-run-tests.bat` | اجرای تست‌ها | ❌ |
| `7-market-symbols.bat` | نمادهای دارای آپشن در بازار | ❌ |
| `8-dashboard.bat` | **داشبورد وب** روی `127.0.0.1:8787` | ❌ |

`_common.bat` بوت‌استرپ مشترک است؛ مستقیم اجرا نکنید.

⏰ **`3-discover-api.bat` را در ساعت بازار اجرا کنید** (شنبه–چهارشنبه، ۹:۰۰–۱۲:۳۰).
بیرون ساعت بازار صفحات داده push نمی‌کنند و گزارش تقریباً خالی می‌شود.

فقط `1` تا `8` دستور خارجی هستند؛ هیچ‌کدام سفارشی ثبت نمی‌کند.

## Getting Started

### ۰. آماده‌سازی محیط (یک بار)

```powershell
cd D:\Project\github\GarnetTrader\option_signal_bot

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

copy config\settings.example.yaml config\settings.yaml
```

آخرین خط برای اجرای با **داده واقعی** لازم است. بدون فایل تنظیمات، ربات روی
پیش‌فرض‌های داخلی کار می‌کند (که آن‌ها هم واقعی‌اند).

⚠️ **دو نکته که بیشترین خطا را می‌سازند:**

| نکته | چرا |
|---|---|
| **در پوشه‌ی `option_signal_bot` باشید**، نه ریشه‌ی ریپو | `main.py` و `.venv` اینجا هستند. از ریشه، خطای `could not be loaded` می‌گیرید. |
| در PowerShell **`.\`** را جا نیندازید | `.venv\...` را PowerShell اسم ماژول می‌فهمد و `Import-Module` پیشنهاد می‌دهد. `.\.venv\...` درست است. |

راه ساده‌تر — یک بار محیط را فعال کنید و بعد `python` خالی کافی است.

⚠️ **این دو خط، دو دستور جداگانه‌اند.** اول این را بزنید و **Enter**:

```powershell
.\.venv\Scripts\Activate.ps1
```

اگر درست کار کرد، پیش‌وند `(.venv)` به prompt اضافه می‌شود:

```
(.venv) PS D:\Project\github\GarnetTrader\option_signal_bot>
```

**بعد** دستور بعدی را بزنید:

```powershell
python main.py --dry-run
```

اگر هر دو را در **یک خط** بنویسید، PowerShell دومی را آرگومانِ `Activate.ps1`
می‌فهمد و خطای `A positional parameter cannot be found` می‌دهد.

اگر PowerShell اجازه‌ی اسکریپت نداد:
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`

- هیچ چیزی روی دیسک نوشته نمی‌شود
- هیچ سفارشی ثبت نمی‌شود


> اگر بخش ۰ را انجام داده‌اید، این مرحله تکمیل است.

### ۳. تنظیمات

```bash
cp config/settings.example.yaml config/settings.yaml
```

فایل نمونه از پیش روی داده **واقعی** TSETMC تنظیم شده (`provider: tsetmc`).
کافی است:
- `market_data.symbols` را با نمادهایی که آپشن دارند پر کنید
  (لیست را با `.\.venv\Scripts\python.exe scripts/fetch_tsetmc_sample.py` ببینید)
- `risk.*` را با اندازه حساب خودتان تنظیم کنید
- برای اجرای آفلاین، `provider` را `fixture` بگذارید (پاسخ ضبط‌شده‌ی واقعی)

**توکن تلگرام** را در فایل ننویسید؛ از متغیرهای محیطی استفاده کنید
(مقدار متغیر محیطی بر مقدار فایل اولویت دارد):

```bash
set TELEGRAM_BOT_TOKEN=123456:ABC...
set TELEGRAM_CHAT_ID=-1001234567890
```

و در `settings.yaml` مقدار `notifiers.telegram.enabled` را `true` کنید.
`config/settings.yaml` در `.gitignore` است تا توکن به گیت نرود.

⚠️ **`settings.yaml` را با `Set-Content` یا `Out-File` ویرایش نکنید.** این‌ها
کامنت‌های فارسی فایل را خراب می‌کنند (double-encode + BOM) و بعدش ربات با یک
traceback خام از PyYAML می‌افتد:
`yaml.reader.ReaderError: unacceptable character #x0081`.

برای ویرایش از VS Code یا Notepad++ استفاده کنید (با encoding **UTF-8 بدون BOM**).
اگر فایل خراب شد، دوباره بسازیدش:

```powershell
Remove-Item config\settings.yaml
copy config\settings.example.yaml config\settings.yaml
```

### ۴. اجرای عادی

```bash
.\.venv\Scripts\python.exe main.py --once            # یک پاس رصد بازار
.\.venv\Scripts\python.exe main.py                   # حلقه دائمی با فاصله poll_interval_seconds
.\.venv\Scripts\python.exe main.py --json            # چاپ سیگنال‌ها به‌صورت JSON
.\.venv\Scripts\python.exe main.py --symbols خودرو شستا وبملت
.\.venv\Scripts\python.exe main.py --backtest        # گزارش کیفیت سیگنال روی داده تاریخی
```

> بیرون ساعت بازار، `--once` فقط `بازار بسته است` می‌دهد و برمی‌گردد.
> برای تست در بازار بسته، در `settings.yaml` مقدار `general.run_only_when_market_open`
> را `false` بگذارید — داده از TSETMC واقعی می‌آید ولی مظنه‌ها آخرین وضعیت روز قبل‌اند.

> **اگر خطای تنظیمات گرفتید:** وقتی `settings.yaml` وجود دارد ولی PyYAML
> نصب نیست، ربات **متوقف می‌شود**. یعنی نمادها، سقف ریسک و پارامترهای
> استراتژی شما اعمال نمی‌شود — بهتر است بلند خطا بدهد تا بی‌صدا با
> تنظیمات دیگری کار کند.

### ۶. داده واقعی بازار (بدون لاگین و بدون توکن)

زنجیره آپشن و تاریخچه نماد پایه از **API عمومی TSETMC** می‌آید؛ هیچ احراز هویتی،
کوکی یا حساب کارگزاری لازم نیست:

| داده | endpoint |
|---|---|
| زنجیره کامل آپشن بازار (یک درخواست) | `cdn.tsetmc.com/api/Instrument/GetInstrumentOptionMarketWatch/{market}` |
| تاریخچه روزانه نماد پایه | `cdn.tsetmc.com/api/ClosingPrice/GetClosingPriceDailyList/{insCode}/0` |

هر ردیف پاسخ دیده‌بان، یک استرایک با **جفت** کال و پوت است و قیمت لحظه‌ای نماد پایه
(`pDrCotVal_UA`) و کد یکتای آن (`uaInsCode`) را هم دارد. نتیجه:

- کل بازار با یک درخواست می‌آید، نه یکی به‌ازای هر نماد
- قیمت پایه و پرمیوم آپشن از **یک پاسخ و یک لحظه**اند (اختلاف منبع، محاسبه IV را خراب می‌کند)
- نگاشت نماد→`insCode` از همان پاسخ ساخته می‌شود؛ به جدول نماد جداگانه نیازی نیست

دیدن لیست نمادهایی که آپشن دارند و وضعیت بازار:

```bash
.\.venv\Scripts\python.exe scripts/fetch_tsetmc_sample.py                 # گزارش
.\.venv\Scripts\python.exe scripts/fetch_tsetmc_sample.py --save-fixture  # به‌روزرسانی نمونه تست
```

**سه لایه داده** پشت همان اینترفیس، با `option_chain.provider` انتخاب می‌شوند:

| provider | داده | کاربرد |
|---|---|---|
| `tsetmc` | زنده | اجرای واقعی |
| `fixture` | پاسخ واقعی **ضبط‌شده** | تست آفلاین، بازتولید یک روز خاص |

**گیت‌های کیفیت داده** (`option_chain.quality`) لازم‌اند، نه تشریفاتی: در یک اجرای
واقعی روی خودرو، ۲۳ قرارداد از ۷۸ حذف شد (۱۱ اسپرد پهن، ۱۲ بدون موقعیت باز).
هر حذف در لاگ شمرده می‌شود تا بی‌صدا نباشد.

### ۷. کشف API پلتفرم کارگزاری (ایزی‌تریدر / emofid)

آدرس درست پلتفرم **`easytrader.ir`** است (متعلق به مفید، و ارجاع‌دهنده به `emofid.com`).
⚠️ `easytrader.com` یک صفحه‌ی **فروش دامنه**ی بی‌ربط است؛ هرگز اعتبارنامه‌تان را آن‌جا وارد نکنید.

TSETMC داده‌ی بازار را می‌دهد ولی سه چیز را نمی‌دهد: **پوزیشن و موجودی حساب**،
**عمق مظنه**، و **push زیرثانیه**. برای آن‌ها به سشن احرازهویت‌شده‌ی کارگزاری نیاز است.
گام اول، کشف سطح API است — با دو مسیر:

> ⏰ **حتماً در ساعت بازار اجرا کنید** (شنبه–چهارشنبه، ~۹:۰۰ تا ۱۲:۳۰).
> در بازار بسته، دیده‌بان و عمق مظنه هیچ داده‌ای push نمی‌کنند و گزارش تقریباً خالی
> درمی‌آید. تست‌شده: اجرای یک‌دقیقه‌ای بیرون ساعت بازار فقط ۲ endpoint داد که
> هر دو آنالیتیکس بودند.

**مسیر ۱ — مرورگر قابل‌مشاهده (توصیه‌شده)**

نصب یک‌باره:
```bash
.\.venv\Scripts\python.exe -m pip install playwright
```
اگر Chrome سیستم را دارید، به `playwright install` نیازی نیست؛ اسکریپت با
`channel="chrome"` همان Chrome خودتان را می‌راند (بدون دانلود ~۴۰۰ مگابایتی).

اجرا:
```bash
.\.venv\Scripts\python.exe scripts/emofid_login.py --url https://easytrader.ir --minutes 15
```

چه اتفاقی می‌افتد:
1. یک پنجره‌ی واقعی Chrome باز می‌شود و به `easytrader.ir` می‌رود
2. **خودتان** نام کاربری، رمز و OTP را وارد می‌کنید — اسکریپت هیچ فرمی پر نمی‌کند
3. بعد از لاگین، این صفحات را باز کنید (هرچه بیشتر، فهرست کامل‌تر):
   **دیده‌بان بازار آپشن**، **سبد دارایی/پوزیشن**، **موجودی حساب**،
   **عمق مظنه یک نماد آپشن**
4. برای پایان زودتر از ۱۵ دقیقه: `Ctrl+C`

**مسیر ۲ — بدون هیچ نصبی (HAR)**

اگر نمی‌خواهید playwright نصب کنید یا مرورگر را به اسکریپت بسپارید:

1. Chrome → `F12` → تب **Network**
2. تیک **«Preserve log»** را بزنید
3. لاگین کنید و همان صفحات بالا را باز کنید
4. راست‌کلیک روی لیست درخواست‌ها → **«Save all as HAR with content»**
5. سپس:

```bash
.\.venv\Scripts\python.exe scripts/har_to_inventory.py مسیر\فایل.har
```

خروجی هر دو مسیر یکی است: `var/emofid/api_inventory.md` و `.json`.

**بعد از اجرا، این‌ها را در گزارش نگاه کنید:**

```bash
type var\emofid\api_inventory.md
```

- هر endpoint مربوط به **پوزیشن / موجودی / سبد** → ورودی آداپتر `AccountDataSource`
- **اتصال سوکت** (SignalR/WebSocket) → مسیر `RealtimeQuoteSource` برای push زیرثانیه
- **هدرهای احراز هویت** (`authorization` یا `cookie`) → نحوه‌ی نگه‌داشتن سشن

**تضمین حریم خصوصی — «شکل را ضبط کن، نه داده را»:** برای نوشتن آداپتر، نام فیلدها
و نوعشان کافی است؛ مقدار موجودی و توکن هیچ‌وقت لازم نیست. پس:

| داده | چه چیزی ثبت می‌شود |
|---|---|
| بدنه‌ی پاسخ | فقط اسکلت نوع‌ها: `{"balance": "number"}` نه `{"balance": 987654321}` |
| هدر احراز هویت | فقط **نوعش**: `Bearer <REDACTED>` |
| شناسه در مسیر URL | `/accounts/<NUM>/positions` |
| پارامتر حساس در query | `token=<REDACTED>` (ولی `type=option` می‌ماند چون مفید است) |
| فریم SignalR | فقط نام متد (`OnBestLimitChanged`)، نه آرگومان‌ها |

این تضمین **تست دارد**: `tests/test_api_inventory.py` یک HAR ساختگی با توکن و کد ملی و
موجودی جعلی می‌سازد و بررسی می‌کند هیچ‌کدام در خروجی نباشند.

⚠️ دو فایل حساس‌اند و زیر `var/` (در `.gitignore`) می‌مانند: `session.json`
(معادل دسترسی به حساب) و فایل HAR خام. **گزارش خروجی** قابل اشتراک است، ولی
قبلش یک مرور چشمی بکنید.

**پاس تمیزکاری معماری** (برای گسترش راحت در آینده)

| کار | چه چیزی را آسان می‌کند |
|---|---|
| `bootstrap.py` — لایه wiring جدا از CLI | افزودن entrypoint دوم (داشبورد، نوتبوک) بدون کپی‌کردن wiring |
| `config/loader.py` — تک‌منبعِ پیش‌فرض‌ها + ادغام عمیق | بازنویسی جزئی yaml دیگر بقیه پارامترها را پاک نمی‌کند |
| `strategies/registry.py` با دکوریتور `@register_strategy` | افزودن استراتژی = یک فایل + یک خط import، بدون دست‌زدن به `main.py` |
| رجیستری provider و notifier در `bootstrap.py` | افزودن TSETMC یا کانال جدید = یک ورودی دیکشنری |
| `build_dataclass` با نادیده‌گرفتن کلید ناشناخته | یک غلط‌املایی در yaml دیگر ربات را با TypeError نمی‌خواباند |
| provider اشتباه = خطای خوانا در startup | خطای تنظیمات زودتر و واضح‌تر دیده می‌شود |
| خروجی‌های اجرا به `var/` منتقل شد | پوشه‌های کد، کد می‌مانند |
| `pyproject.toml` (pytest + ruff) | لینت و تست یکدست، آماده CI |
| تست گارد سراسری AST | هر ماژول **آینده** هم خودکار از import کردن `execution` منع می‌شود |

## معماری

```
market_data_client ─┐
                    ├─→ StrategyContext ─→ strategies ─→ Signal ─┬─→ notifiers (تلگرام/کنسول)
option_chain_client ┘                          ↑                 └─→ storage/signal_log (Audit)
                                        risk_calculator
                                    (تعداد و حد ضرر پیشنهادی)

bootstrap.py  → از settings همه اجزای بالا را می‌سازد (DI)
main.py       → فقط CLI و حلقه اجرا

execution/order_executor_interface.py   ← جدا و منفصل؛ هیچ‌کس در این مایل‌استون آن را صدا نمی‌زند
```

قواعد سختی که رعایت و **تست** شده‌اند:

| قاعده | جای اعمال |
|---|---|
| استراتژی فقط `Signal` برمی‌گرداند | `strategies/base_strategy.py` |
| استراتژی به نوتیفایر/دیتابیس/اجرا دسترسی ندارد | `StrategyContext` فقط داده می‌دهد + تست AST |
| هیچ ماژولی بیرون از `execution/` آن را import نمی‌کند | تست گارد سراسری در `tests/test_signal_generator.py` |
| اندازه پوزیشن و حد ضرر فقط «پیشنهاد» است | `risk/risk_calculator.py` |
| هیچ I/O شبکه‌ای در لایه اجرا نیست | گارد AST در `tests/test_signal_generator.py` |

### افزودن یک استراتژی جدید

```python
# strategies/my_strategy.py
from strategies.base_strategy import BaseStrategy
from strategies.registry import register_strategy

@register_strategy
class MyStrategy(BaseStrategy):
    name = "my_strategy"

    @classmethod
    def default_params(cls):
        return {"threshold": 2.0}

    def generate(self, context):
        contract = self.select_contract(context, "call", moneyness=0.03)
        return [] if contract is None else [
            self.build_signal(context, contract, Side.BUY, "دلیل سیگنال")
        ]
```

بعد یک خط `from strategies.my_strategy import MyStrategy` به `strategies/__init__.py`
اضافه کنید. تمام — نه `main.py` تغییر می‌کند و نه `bootstrap.py`.
